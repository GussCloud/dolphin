# Mobile internationalization

The mobile app ships the desktop's seven locales: `en`, `zh`, `ko`, `ja`, `es`, `fr`, `pt-BR`
(`SUPPORTED_UI_LOCALES` in `src/shared/ui-locale.ts`). Strings live in small typed TypeScript
catalogs, one namespace per feature. There is no i18next and no central registry: a screen imports
its own namespace and nothing else, so features can be translated in parallel without touching
shared files.

## Layout

```
mobile/src/i18n/
  mobile-i18n-catalog.ts        types, defineMobileCatalog
  mobile-locale-state.ts        active locale store, translate() for non-React code
  use-mobile-translation.ts     useMobileTranslation(), useMobileLocale()
  mobile-locale-provider.tsx    <MobileLocaleProvider> (mounted in app/_layout*.tsx)
  mobile-language-preference.ts AsyncStorage key `dolphin:uiLanguage`
  catalogs/<namespace>/
    en.ts       source of truth
    zh.ts ko.ts ja.ts es.ts fr.ts pt-BR.ts
    index.ts    defineMobileCatalog({...}) -> <namespace>Catalog
    <namespace>-catalog.test.ts
```

Existing namespaces: `settings` (`src/settings/**` and the settings routes in `app/`) and
`app-routes` (pairing and onboarding routes in `app/`). Do not add keys to a namespace you do not
own; create your own.

## Adding a namespace

1. Name it after the directory you own, in kebab-case: `src/session` → `session`,
   `src/source-control` → `source-control`. Export names are the camelCase form: `sessionEn`,
   `sessionPtBR`, `sessionCatalog`.
2. Create `catalogs/<namespace>/en.ts`. Keys are flat camelCase, grouped by comments; a common
   prefix per screen keeps related keys together (`historyEmpty`, `historyLoadError`). Keep the
   `as const satisfies` tail: `as const` is what lets `t()` type the `{placeholders}`.

   ```ts
   import type { MobileCatalogSource } from '../../mobile-i18n-catalog'

   export const sessionEn = {
     title: 'Session',
     renameTitle: 'Rename {name}',
     unreadCount: { one: '{count} unread message', other: '{count} unread messages' }
   } as const satisfies MobileCatalogSource
   ```

3. Create one file per other locale, typed against English. A missing or extra key fails `tsc`:

   ```ts
   import type { MobileLocaleMessages } from '../../mobile-i18n-catalog'
   import type { sessionEn } from './en'

   export const sessionPtBR: MobileLocaleMessages<typeof sessionEn> = {
     title: 'Sessão',
     renameTitle: 'Renomear {name}',
     unreadCount: { one: '{count} mensagem não lida', other: '{count} mensagens não lidas' }
   }
   ```

4. Create `index.ts`, copying `catalogs/settings/index.ts`:

   ```ts
   export const sessionCatalog = defineMobileCatalog({
     en: sessionEn,
     zh: sessionZh,
     ko: sessionKo,
     ja: sessionJa,
     es: sessionEs,
     fr: sessionFr,
     'pt-BR': sessionPtBR
   })
   ```

5. Add `catalogs/<namespace>/<namespace>-catalog.test.ts`, copying
   `catalogs/settings/settings-catalog.test.ts`. Types pin the key sets; this test pins the
   `{placeholders}` inside each translation and rejects empty strings.

## Message format

- Interpolation is `{name}` (single braces, unlike desktop's `{{name}}`). Values are
  `string | number`. Names are typed from the English string: `t('renameTitle')` without
  `{ name }` is a compile error.
- Plurals are `{ one, other }` objects, chosen by `vars.count` with CLDR rules, matching desktop
  i18next's `key_one` / `key_other`. `zh`, `ja`, `ko` always use `other` (write both anyway, they
  may be identical); `fr` and `pt-BR` treat 0 as `one`. A plural requires `{ count }`.
- Build whole sentences. Never concatenate fragments (`'Allow X' + (a ? ' and Y' : '')`): use two
  keys, because word order differs per language.

## Using it

In a component:

```tsx
import { sessionCatalog } from '../i18n/catalogs/session'
import { useMobileTranslation } from '../i18n/use-mobile-translation'

const t = useMobileTranslation(sessionCatalog)
<Text>{t('title')}</Text>
<Text>{t('unreadCount', { count })}</Text>
```

`t` is stable until the language changes, so it belongs in `useCallback`/`useMemo`/`useEffect`
deps. The hook re-renders on a language change and works without the provider (tests).

Option lists defined at module scope must not hold translated labels, or they freeze the first
locale. Store the key and translate at render:

```ts
const MODES = [{ value: 'hold', labelKey: 'modeHold' }] as const
// render: t(mode.labelKey)
```

To pass `t` to a helper, type it as `MobileTranslate<typeof sessionEn>` (from
`mobile-i18n-catalog`).

Outside React (alerts, notifications, operations modules):

```ts
import { translate } from '../i18n/mobile-locale-state'
Alert.alert(translate(sessionCatalog, 'deleteTitle', { name }))
```

`translate()` reads the active locale when called. Never call it at module top level.

Other exports: `useMobileLocale()` / `getActiveMobileLocale()` return the active
`SupportedUiLocale`, e.g. for `toLocaleString(locale)` or `Intl.DateTimeFormat(locale)`.

## What to translate

Translate visible text, `accessibilityLabel`/`accessibilityValue` text, picker titles, placeholders
and user-facing error messages. Keep as-is: product names (Dolphin, Relay, Claude, Codex,
Chat UI), commands, flags, paths, URLs, code literals, and log or `console.*` text. Use Brazilian
Portuguese for `pt-BR`. When the desktop already says the same thing, reuse its wording from
`src/renderer/src/i18n/locales/<locale>.json` for consistency.

## Tests stay English

`vitest.setup.ts` pins the system locale to `en` and `vitest.config.ts` sets `LC_ALL` for the
workers, so the default "System default" preference resolves to English and existing assertions on
English copy keep passing. A test that needs another locale calls
`applyMobileLanguagePreference('pt-BR')` (or `setMobileSystemLocaleOverride('ja-JP')`) and restores
`'system'` / `'en'` in `afterEach`.

## Runtime

The device locale comes from `Intl.DateTimeFormat().resolvedOptions().locale` (Hermes), mapped
through `normalizeSupportedUiLocale` (unsupported variants such as `pt-PT` and `zh-TW` fall back to
English, as on desktop). The Language setting (Settings → Language) stores `system` or a locale
under `dolphin:uiLanguage`; `MobileLocaleProvider` loads it at startup, re-reads the device locale
when the app returns to the foreground, and the hybrid page receives the key through the page
storage allowlist.
